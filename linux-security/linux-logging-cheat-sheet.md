# Linux Logging & Security Monitoring

A technical reference guide covering core Linux log sources, Systemd Journal (`journalctl`) queries, and basic `auditd` configurations for SOC operations.

---

## 1. Core Linux System Logs (/var/log/)

| Log File | Primary Purpose | Analysis Focus |
| :--- | :--- | :--- |
| `/var/log/auth.log` (Ubuntu/Debian)<br>`/var/log/secure` (RHEL/CentOS) | Authentication & Authorization | SSH failures, `sudo` usage, user account creation, brute-force attempts |
| `/var/log/syslog` (Ubuntu/Debian)<br>`/var/log/messages` (RHEL/CentOS) | General System Activity | Service lifecycle events, application errors, background tasks |
| `/var/log/kern.log` | Kernel Diagnostics | Device attachments, Out-Of-Memory (OOM) events, kernel module loads |
| `/var/log/cron` | Task Scheduler | Cron job additions, modifications, and executions |

---

## 2. Filtering Logs via Systemd Journal (journalctl)

Modern Linux distributions utilize `systemd-journald` for binary logging. Common query syntaxes include:

* `journalctl -u ssh.service` — View logs specifically generated by the SSH service.
* `journalctl --since "1 hour ago"` — Display events logged within the last hour.
* `journalctl -p err` — Filter for errors and critical system priority levels.
* `journalctl -f` — Monitor system log output in real time.

## 3. Kernel Auditing Framework (auditd)

The `auditd` service tracks system-level events (syscalls, file access, process creation) at the kernel layer.

### Useful Commands:
* `auditctl -l` — List all currently active audit rules.
* `ausearch -m USER_LOGIN -sv no` — Search for failed user login attempts.
* `ausearch -m EXECVE` — Query process execution history.

### Core Rules (/etc/audit/rules.d/audit.rules):
```bash
# Monitor sudo execution for privilege escalation
-w /usr/bin/sudo -p x -k privilege_escalation

# Track modifications to identity databases
-w /etc/passwd -p wa -k identity_changes
-w /etc/shadow -p wa -k identity_changes

# Monitor Cron directory changes for persistence
-w /etc/cron.d/ -p wa -k persistence_cron
```

## SOC Analyst Notes
1. **SSH Brute-Force Detection**: Search `/var/log/auth.log` or `/var/log/secure` for frequent `Failed password for invalid user` entries originating from a single IP.

2. **Sudo Anomalies**: Investigate interactive shells spawned via `sudo` (`sudo su`, `sudo bash`) or unexpected utilities run with elevated privileges.

3. **Cron Persistence**: Any write activity (`-p wa`) in `/etc/cron*` or `/var/spool/cron/crontabs/` serves as a high-fidelity indicator of persistent access.
